\title{The Wrong Memory at the Right Time:\\
Verifying Retrieval Admissibility in Long-Term Agents}

\author{Anonymous Author(s)}

\begin{abstract}
Long-term agent memory is usually evaluated by whether it retrieves relevant
evidence.  Relevance is necessary but not sufficient: evidence can directly answer
a question while belonging to the wrong principal, violating policy, or representing
a state that is invalid for the query's intent.  We formulate \emph{retrieval
admissibility}, a query-conditioned verification target that separates relevance
from scope, policy, and lifecycle compatibility.  We instrument the memory path as
four distinct events---stored, retrieved, exposed, and disclosed---and define
matched-recall contamination with explicit bounds for incompletely labeled evidence.
We then apply this protocol to frozen public-source evaluations derived from GateMem,
RHELM, and MemOps.  Across \NaturalQueryCount{} queries, trusted namespace support
increases source-macro evidence recall by \NamespaceRecallDelta{} (95\% CI
\NamespaceRecallDeltaCI{}) and reduces a preregistered penalized conservative risk
score by \NamespaceContaminationReduction{} (signed-delta 95\% CI
\NamespaceContaminationDeltaCI{}).  Conditional matched-prefix bounds remain wide
because same-namespace labels are incomplete.  Additional
threshold and cluster routing does not establish incremental utility.  At fixed
GateMem checkpoints, target exposure is strongly associated with answer disclosure
for two separately executed same-provider readers, while reducing exposure also incurs
utility and over-refusal costs.  The contribution is an auditable verification
protocol and empirical diagnosis, not a new memory index or a causal leakage claim.
\end{abstract}

\section{Introduction}

Persistent memory lets an agent accumulate user facts, task experience, and
environment state beyond one context window.  Existing evaluations therefore ask
whether the system can recover evidence from long histories
\citep{wu2025longmemeval,wu2026longmemevalv2,zhang2026rhelm}.  That question misses a
deployment-critical distinction.  Figure~\ref{fig:pipeline} shows four cases from
our audited public-source packets.  A market query retrieves a topically similar
market memory from another principal.  A current Lisbon-departure query encounters
an invalidated March 7 record after March 14 has been confirmed.  A phone-memory
request must retain model and carrier details while withholding a battery habit the
user explicitly asked the system to forget.  Conversely, superseded dose schedules
remain necessary when a query asks how metformin timing changed over time.  The same
stored record can therefore be usable, inadmissible, or unresolved depending on the
query, principal, policy, and time.  Recent benchmarks expose individual parts of
this problem through
shared-memory governance \citep{ren2026gatemem,mireshghallah2026cimemories}, explicit
lifecycle operations \citep{hao2026memops}, and stale-state reasoning
\citep{chao2026stale}.  What is still missing is a compact verification object that
can be measured at retrieval time and traced to downstream use.

We study this gap as an evaluation problem rather than proposing another memory
architecture.  Our central object is \emph{query-conditioned admissibility}: whether
a memory is within scope, policy-allowed, and lifecycle-compatible for a particular
query and time.  The verification layer checks each ranked candidate, emits an
explicit use/drop reason, and preserves its identity through four observable stages:
stored, retrieved, exposed, and disclosed.  This makes failures localizable.  A
store can contain inadmissible material without retrieving it; a router can retrieve
a candidate without exposing it; and a reader can be exposed to a target without
disclosing it in the answer.

Our contributions are:
\begin{itemize}
  \item a formal distinction between relevance and retrieval admissibility, together
  with a stored--retrieved--exposed--disclosed observation model;
  \item matched-recall contamination metrics with label coverage and conservative
  lower and upper bounds under unresolved evidence;
  \item a hash-bound public-source audit over \NaturalGroupCount{} groups,
  \NaturalMemoryCount{} memories, and \NaturalQueryCount{} queries, showing that
  trusted namespace support provides the main retrieval gain while two additional
  routing refinements do not; and
  \item a separate exposure/disclosure analysis that identifies what the retrieval
  measurements can and cannot support.
\end{itemize}

\section{Related Work}

\paragraph{Long-term memory evaluation.}
LongMemEval decomposes memory systems into indexing, retrieval, and reading and
tests extraction, multi-session reasoning, temporal reasoning, updates, and
abstention \citep{wu2025longmemeval}.  LongMemEval-V2 extends evaluation to
environment experience and explicitly measures context gathering and latency
\citep{wu2026longmemevalv2}.  RHELM introduces heterogeneous, temporally evolving
sources \citep{zhang2026rhelm}, while MemOps evaluates explicit remember, forget,
update, and reflection operations \citep{hao2026memops}.  These resources motivate
our focus on evidence state and provenance rather than treating memory as a static
bag of facts.

\paragraph{Governance and contextual validity.}
GateMem evaluates utility, access control, and active forgetting in multi-principal
memory \citep{ren2026gatemem}; CIMemories studies context-dependent information-flow
violations \citep{mireshghallah2026cimemories}; and STALE tests whether models reject
invalidated premises \citep{chao2026stale}.  We do not replace these benchmarks.
Instead, we define a common retrieval-time verification layer and demonstrate how
their signals can be reported without collapsing scope, lifecycle, exposure, and
answer disclosure.

\paragraph{Analytical agent evaluation.}
AgentBench and AgentBoard broaden agent evaluation beyond static language tasks
\citep{liu2024agentbench,ma2024agentboard}; HELM emphasizes multi-metric transparent
evaluation \citep{liang2023helm}.  Our protocol follows this analytical stance:
final-answer accuracy alone cannot tell whether an answer was supported by
admissible evidence.  Because model-based evaluation can introduce systematic
biases \citep{liu2023geval}, we report reader identities separately and do not pool
their estimates.

\section{Verification Protocol}

\subsection{Relevance is not admissibility}

For a query $q$ at time $t$, let $\mathcal{R}_q$ denote memories judged relevant,
$\mathcal{N}_q$ memories within the allowed namespace or principal scope,
$\mathcal{P}_q$ memories permitted by the governing policy, and
$\mathcal{L}_{q,t}$ memories lifecycle-compatible with the query intent.  The
admissible and usable sets are
\begin{align}
\mathcal{A}_{q,t}
&= \mathcal{N}_q\cap\mathcal{P}_q\cap\mathcal{L}_{q,t},
\label{eq:admissible}\\
\mathcal{U}_{q,t}
&= \mathcal{R}_q\cap\mathcal{A}_{q,t}.
\label{eq:usable}
\end{align}
Membership on each axis is three-valued: positive, negative, or unresolved.  A known
violation excludes the memory; all memberships must be positive to establish
usability; otherwise the label remains unresolved.  In the frozen released-field
evaluation, current records are lifecycle-compatible with current-state and history
queries, while stale or superseded records are retained for history and rejected for
current-state queries.  Relevance is assessed separately, so retention does not imply
that every historical record is useful.  Equations~\ref{eq:admissible}--%
\ref{eq:usable} define a verification target, not a method for inferring latent
scope, policy, intent, or state.

\paragraph{Operational view.}
For every returned memory ID, the evaluator records four labels: relevance,
namespace membership, policy permission, and lifecycle compatibility
(Figure~\ref{fig:pipeline}b).  Any known violation on the latter three axes excludes
the item from the admissible set.  An item is established as usable only when all
four labels are positive; every remaining case is unresolved.  Trusted namespace
metadata can constrain the candidate support before semantic ranking.  Policy and
lifecycle checks can then be applied before prompt assembly when their labels are
available.  The protocol outputs candidate IDs, exclusion reasons, unresolved
status, and the subsequent exposure and disclosure trace.  It does not silently
replace missing labels or claim to infer unreleased metadata.

\subsection{Four observable stages}

We log whether each memory was \emph{stored}, returned by retrieval, included in the
reader prompt (\emph{exposed}), and detected in the answer (\emph{disclosed}).  These
events answer different questions.  Retrieval metrics diagnose the candidate
selection mechanism.  Exposure metrics include prompt assembly and truncation.
Disclosure metrics depend additionally on the reader and a fixed scorer; they do not
identify the reader's internal reasoning.  Causal claims require an intervention
on exposure; observational disagreement between routes only identifies association.

\subsection{Matched-recall contamination with incomplete labels}

Let $A_q$ be the set of known usable evidence anchors for query $q$, and let a route
rank memories as $r_1,\ldots,r_n$.  For target recall $\tau$, we score the smallest
prefix $P_q(\tau)$ that reaches
\[
\frac{|P_q(\tau)\cap A_q|}{|A_q|}\geq\tau.
\]
This compares contamination only after systems reach the same evidence-recall
target.  A known contaminant is a prefix item whose released labels establish that
it is non-usable for $q$; unresolved items are not silently converted to negatives.
If the matched prefix contains $c$ known contaminants, $u$ unresolved items, and
$N$ total items, we report
\[
C_q^{K}=\frac{c}{N-u},\qquad
\gamma_q=\frac{N-u}{N},\qquad
[C_q^{L},C_q^{U}]=\left[\frac{c}{N},\frac{c+u}{N}\right].
\]
The upper bound treats every unresolved item as contamination.  A query is feasible
when the returned route reaches $\tau$.  For the preregistered setting-selection and
primary aggregate risk score, recall failure cannot look safe:
\[
\widetilde C_q^{U}=
\begin{cases}
C_q^{U}, & q\text{ is feasible and }C_q^{U}\text{ is defined},\\
1, & \text{otherwise}.
\end{cases}
\]
We call the mean of $\widetilde C_q^{U}$ the \emph{penalized conservative risk};
it combines incomplete-label risk with a worst-case penalty for infeasibility and is
not a pure conditional contamination estimate.  We therefore report it together
with feasible rate and the conditional $C^K$, $\gamma$, $C^L$, and $C^U$ summaries.
Queries without known usable anchors are recall-unevaluable rather than assigned
zero.  Typed exposure rates separately identify wrong scope, policy disallowance,
and lifecycle incompatibility.

\section{Evaluation}

\subsection{Evidence surfaces and frozen populations}

We evaluate the protocol on three complementary surfaces.  They answer different
questions and are never pooled into one score.

\paragraph{GateMem exposure and disclosure.}
GateMem supplies fixed privacy and safety checkpoints with leak-target annotations
\citep{ren2026gatemem}.  The frozen bundle contains 91 episodes and 2,218 checkpoints
(728 utility, 727 privacy, and 763 safety) under three released routes.  The primary
exposure analysis contains
\ReaderDiscordantCount{} checkpoints where two frozen routes disagree on whether
the target reaches the prompt.  Incremental prediction uses
\ReaderPredictionCount{} held-out checkpoint rows.  We execute
\texttt{gpt-4o-mini-2024-07-18} (Reader A) and
\texttt{gpt-4o-2024-08-06} (Reader B) separately.  Both are OpenAI snapshots:
this is same-provider cross-reader robustness, not cross-provider replication.
A separate frozen comparison retains the source study's G0 baseline and G1 stricter
exposure-filtering labels.  It contains \GOneLeakageCount{} leakage-eligible
checkpoints and a distinct \GOneUtilityCount{} bounded-utility population.

\paragraph{Public-source retrieval.}
The retrieval audit combines public RHELM and MemOps sources
\citep{zhang2026rhelm,hao2026memops}: \NaturalGroupCount{} groups,
\NaturalMemoryCount{} memories, and \NaturalQueryCount{} queries.  RHELM contributes
523 queries across seven persona namespaces; each candidate corpus contains all
same-split conversation turns strictly earlier than the query date.  MemOps
contributes 3,244 probes across 80 profile namespaces; each global arm receives all
method-visible dialogue memories in the evaluation split.  No candidate
subsampling or positive injection is used.  A pinned Qwen3-Embedding-8B revision
produces 4,096-dimensional, unit-normalized last-token embeddings with a 512-token
limit; ranking uses exact float32 inner product and stable memory-ID ties.

Development selection uses a disjoint 23-group population with 45,978 memories and
1,104 queries.  Exactly one configuration for each of nine frozen arms was selected
there and then applied without evaluation retuning, query deletion, output repair,
or fallback changes, yielding \NaturalRouteRows{} complete method-query routes and
scores.

\subsection{Retrieval arms and frozen selection}

The nine arms share memory units, query text, embedding revision, and top-$k$ budget.
Four global controls are BM25, dense retrieval, BM25--dense reciprocal-rank fusion,
and dense retrieval with a released-order recency feature.  Three support or
lifecycle arms are namespace dense, namespace current-only, and a released-intent
lifecycle upper bound.  The last two arms are development-selected namespace-local
threshold and centroid-cluster routers.  The upper-bound arm observes rather than
infers intent and state.  Both routers use namespace-local dense fallback, so neither
can cross a trusted namespace.  Appendix~\ref{app:arms} gives formulas and all
selected settings.

Every selected arm has $k=100$ and is evaluated at target evidence recall
$\tau=0.8$.  Selection first macro-averages queries within RHELM and MemOps, then
uses equal source weight and the lexicographic objective: maximize feasible rate,
minimize penalized conservative risk, minimize resolved contamination, maximize
evidence recall, minimize candidates scored, and finally use stable setting ID.
The grid contains 165 settings; evaluation data never enter selection.

\subsection{Metrics and uncertainty}

For GateMem checkpoint $q$, let $D_q$ be its unordered route pairs with different
target-exposure labels.  Orient each pair as exposed minus unexposed and define
\[
d_q=\frac{1}{|D_q|}\sum_{(a,b)\in D_q}
  \left(Y_{qa}^{\mathrm{exposed}}-Y_{qb}^{\mathrm{unexposed}}\right),
\qquad
\widehat{\mathrm{RD}}=\frac{1}{|Q_D|}\sum_{q\in Q_D}d_q ,
\]
where $Y$ is rule-based final-answer target disclosure.  Averaging inside a
checkpoint prevents checkpoints with multiple discordant pairs from receiving
extra weight.  Confidence intervals use 10,000 episode-cluster bootstrap
replicates.  A secondary leave-one-episode-out logistic analysis predicts disclosure
from route identity, domain, query type, route non-emptiness, and standardized route
width; the augmented model adds target exposure.  We report augmented-minus-baseline
Brier score and log loss.  G1-minus-G0 deltas are reported separately for leakage,
bounded utility accuracy, and over-refusal because the eligible populations differ.
These route comparisons are observational.

For retrieval, the primary outcomes are source-macro evidence recall, feasibility
at $\tau$, and penalized conservative risk.  Conditional matched-prefix
contamination, coverage, and bounds remain separate descriptive outcomes.  We also
report wrong-scope leakage and prohibited stale or superseded exposure.  RHELM and
MemOps receive equal source weight so that MemOps does not dominate by size.  Paired
95\% intervals use 10,000 replicates, resampling personas within RHELM and base
profiles within MemOps before replicate-wise equal-source averaging.  Local timing
and candidate counts are diagnostics only and are not production cost estimates.

All empirical numbers, tables, and figures below are generated from hash-bound
normalized evidence after claim-boundary validation.

\subsection{Evaluation boundaries}

The public-source retrieval run makes no provider, reader, judge, or paid calls and
does not measure downstream answer quality.  It is not an official RHELM or MemOps
submission.  The GateMem analyses are open-label, observational diagnostics rather
than an official benchmark result or a causal intervention.  The three evidence
surfaces remain distinct throughout reporting.

\subsection{Exposure predicts answer disclosure across readers}

Across \ReaderDiscordantCount{} fixed discordant checkpoints, Reader A has an
exposed-minus-unexposed answer-disclosure risk difference of
\ReaderARiskDifference{} (95\% CI \ReaderARiskDifferenceCI{}); Reader B yields
\ReaderBRiskDifference{} (\ReaderBRiskDifferenceCI{}; Figure~\ref{fig:evidence}a).
The separately executed estimates agree in direction but are not pooled.

On \ReaderPredictionCount{} held-out rows, adding exposure improves leakage
prediction for both readers.  Reader A changes Brier score by
\ReaderABrierDelta{} (\ReaderABrierDeltaCI{}) and log loss by
\ReaderALogLossDelta{} (\ReaderALogLossDeltaCI{}); Reader B changes them by
\ReaderBBrierDelta{} (\ReaderBBrierDeltaCI{}) and
\ReaderBLogLossDelta{} (\ReaderBLogLossDeltaCI{}), respectively
(Figure~\ref{fig:evidence}b).  Exposure therefore carries predictive information
beyond the frozen baseline, but the result remains an association rather than a
causal mediation estimate.

\subsection{Filtering exposes a safety--utility frontier}

On \GOneLeakageCount{} leakage-eligible checkpoints, the stricter G1 route changes
answer leakage by \GOneLeakageDelta{} (95\% CI \GOneLeakageDeltaCI{}) relative to
G0.  On the separate \GOneUtilityCount{} bounded-utility checkpoints, it changes
utility accuracy by \GOneUtilityDelta{} (\GOneUtilityDeltaCI{}) and over-refusal by
\GOneRefusalDelta{} (\GOneRefusalDeltaCI{}; Figure~\ref{fig:evidence}c).  Filtering
therefore reduces leakage while imposing measurable utility and refusal costs; it
is not uniformly better.

\subsection{Trusted namespace support carries the retrieval gain}

Global dense evidence recall is \GlobalDenseRecall{}, versus
\NamespaceDenseRecall{} with trusted namespace support
(Figure~\ref{fig:retrieval}a,b).  The paired source-macro
gain is \NamespaceRecallDelta{} (\NamespaceRecallDeltaCI{}), and feasible rate
increases from \GlobalDenseFeasible{} to \NamespaceDenseFeasible{}, a difference of
\NamespaceFeasibleDelta{} (\NamespaceFeasibleDeltaCI{}).  Penalized conservative
risk decreases from \GlobalPenalizedRisk{} to \NamespacePenalizedRisk{} (difference
\NamespaceContaminationDelta{}, 95\% CI \NamespaceContaminationDeltaCI{};
Figure~\ref{fig:retrieval}b).  Measured
wrong-scope leakage is \NamespaceWrongScopeLeakage{} for namespace-constrained arms
under trusted released namespaces.  This supports a trusted provenance constraint;
it does not establish performance under noisy or inferred namespaces or downstream
answer improvement.

The conditional matched-prefix view is more qualified
(Figure~\ref{fig:retrieval}c and Table~\ref{tab:matched-prefix}).  Known
contamination and its lower bound are
descriptively smaller under namespace support, but coverage falls from
\GlobalLabelCoverage{} to \NamespaceLabelCoverage{}.  Consequently, the conditional
upper bound remains high and changes from \GlobalUpperBound{} to
\NamespaceUpperBound{}.  The penalized-risk improvement must therefore be read
together with the large feasibility gain, not as evidence that unresolved
same-namespace content disappeared.

\subsection{Additional routing does not add retrieval utility}

Relative to namespace dense, the threshold router changes recall by
\ThresholdRecallDelta{} (\ThresholdRecallDeltaCI{}) and penalized risk
by \ThresholdContaminationDelta{} (\ThresholdContaminationDeltaCI{}).  The cluster
router changes recall by \ClusterRecallDelta{} (\ClusterRecallDeltaCI{}) and
risk by \ClusterContaminationDelta{}
(\ClusterContaminationDeltaCI{}; Figure~\ref{fig:retrieval}d).  The threshold arm
loses recall and slightly worsens the risk score.  It also falls back to
namespace-local dense retrieval on \ThresholdFallbackRate{} of source-macro queries,
so it rarely supplies a distinct route.  The cluster arm selects
\ClusterRouteWidth{} cluster on average and is practically indistinguishable, with
its risk interval crossing zero.
These frozen variants establish no incremental utility beyond the namespace-dense
control, without implying that clustering is universally ineffective.

\subsection{Released fields reveal lifecycle headroom}

Using released intent and lifecycle state changes penalized conservative risk by
\LifecycleContaminationDelta{}
(\LifecycleContaminationDeltaCI{}) and recall by \LifecycleRecallDelta{}
(\LifecycleRecallDeltaCI{}).  Over the \LifecycleExposureCount{} eligible exposure
rows, prohibited stale exposure changes by \LifecycleStaleDelta{}
(\LifecycleStaleDeltaCI{}) and prohibited superseded exposure by
\LifecycleSupersededDelta{} (\LifecycleSupersededDeltaCI{};
Figure~\ref{fig:retrieval}d).  The recall interval crosses zero, while all three
admissibility-risk intervals favor the upper-bound arm.  This establishes
diagnostic headroom under observed fields, not that a deployed system can infer
intent or lifecycle state from raw history.

\section{Discussion}

\paragraph{Verification changes the unit of analysis.}
A benchmark score usually asks whether an agent answered correctly.  Retrieval
admissibility asks which evidence was eligible to influence that answer, when, and
under whose scope.  The four-stage trace supports sharper regression tests: a change
can improve retrieval recall while worsening prompt exposure, or reduce exposure
while increasing over-refusal.

\paragraph{Constraints can matter more than routing sophistication.}
In the frozen public-source evaluation, trusted namespace support changes the
candidate support before semantic ranking and produces the main gain.  Additional
threshold and clustering heuristics do not improve upon that control.  This negative
result is useful for agent development: verifier effort should first test provenance
and support constraints before attributing gains to a more elaborate memory index.

\paragraph{Evaluation should preserve unresolved evidence.}
Non-required same-namespace memories are not automatically contaminants.  Treating
them as negative labels would overstate precision; treating them as relevant would
hide risk.  In our results, namespace filtering lowers resolved contamination while
also lowering label coverage, so the conditional upper bound remains high.  Reporting
coverage and lower/upper bounds prevents the penalized aggregate from hiding this
annotation gap.

\section{Limitations and Broader Impact}

The public-source retrieval audit covers RHELM and MemOps only, uses released trusted
namespaces, and has no downstream reader outcome.  Source-macro intervals represent
two source clusters, not broad domain sampling.  The mechanism smoke contains only
16 curated evaluation packets.  The lifecycle result uses released intent and state
fields and is therefore an upper bound.  Local timing and candidate counts do not
support a production cost claim.

The GateMem readers are both OpenAI models and are never pooled.  Exposure/disclosure
differences are observational rather than randomized.  Utility and leakage have
different eligible populations.

Admissibility filters can reduce cross-principal or stale-memory exposure, but they
can also suppress legitimate evidence and encourage over-refusal.  A deployment
should log exclusions, support appeal or audit, and evaluate utility at matched
recall.  Our released package contains content-free aggregates and hashes only; it
excludes raw conversations, model responses, and private data.

\section{Conclusion}

Long-term memory verification should ask more than whether a retrieved item is
topically relevant.  By separating relevance from query-conditioned admissibility,
instrumenting stored--retrieved--exposed--disclosed events, and reporting matched-recall
contamination with uncertainty bounds, we obtain a more diagnostic evaluation of
agent memory.  The frozen evidence points to a practical lesson: trusted provenance
constraints provide clear value, while extra routing complexity requires evidence
beyond an unconstrained baseline.  The protocol turns that lesson into a testable,
auditable contract for future memory systems.

\section{Metric Details}

For a matched prefix, known contamination is undefined when every item is unresolved;
the lower and upper bounds remain defined.  Queries with no known usable anchors are
excluded from recall averages, and the evaluable rate is reported separately.  Macro
averages never impute missing query metrics.  Duplicate ranked memory identifiers,
missing assessments, negative runtime measurements, and non-finite values are
rejected by the reference implementation.

\section{Natural-Corpus Construction and Arms}
\label{app:arms}

RHELM development uses the first three persona-hash groups; evaluation uses the
remaining seven.  For each query, only conversation turns strictly earlier than its
date are candidates.  MemOps development uses the first 20\% of profile-hash groups;
evaluation uses the remaining 80 profiles.  Every method-visible dialogue memory in
the split is a global candidate.  MemOps has no cross-case wall clock, so its recency
arm uses released source order and is not a temporal-freshness claim.

All dense arms use \texttt{Qwen/Qwen3-Embedding-8B} at revision
\nolinkurl{1d8ad4ca9b3dd8059ad90a75d4983776a23d44af}, maximum length 512,
unit-normalized last-token pooling, float32 vectors, exact inner product, and stable
memory-ID tie breaking.  For unit vectors,
\[
s_{\mathrm{dense}}(m,q)=e_m^\top e_q.
\]
The hybrid arm uses reciprocal-rank fusion
\[
s_{\mathrm{RRF}}(m,q)=
\frac{1}{60+\operatorname{rank}_{\mathrm{BM25}}(m)}
+
\frac{1}{60+\operatorname{rank}_{\mathrm{dense}}(m)},
\]
and the recency control uses
$s_{\mathrm{rec}}(m,q)=s_{\mathrm{dense}}(m,q)+\gamma\rho(m)$, where
$\rho(m)\in[0,1]$ is normalized released order.

The threshold router incrementally assigns a memory to its most similar namespace
centroid when $\max_k\cos(e_m,c_k)\geq\theta$ and otherwise creates a cluster.  At
query time it selects at most $L$ centroids above $\theta$.  The cluster router uses
\[
\ell_k(x)=\gamma\log(n_k+\beta)+\frac{\cos(x,c_k)}{\tau},
\qquad
\ell_{\mathrm{new}}(x)=\log\alpha+
\frac{1-\max_j\cos(x,c_j)}{\tau_{\mathrm{new}}},
\]
assigns by the largest existing-or-new score, and routes over existing clusters.
An empty route in either router falls back to namespace-local dense retrieval.

\section{GateMem Scoring and Prediction}

Privacy checkpoints use the released privacy context-leak and answer-leak rules;
safety checkpoints use the corresponding deletion rules.  The disclosure outcome
is the released rule-based end-to-end target indicator.  Utility correctness and
over-refusal are bounded rule-based auxiliary outcomes rather than LLM-judge scores.
Parse failures are handled conservatively as leakage for privacy or safety and as
incorrect plus over-refusal for utility.

The incremental predictor is logistic regression with $C=1$, the \texttt{lbfgs}
solver, and at most 2,000 iterations.  Categorical features are arm, domain, and
query type; additional baseline features are route non-emptiness and standardized
route width.  The augmented model adds only target exposure.  Each held-out episode
is scored by a model fit on all other episodes.  Brier and log-loss differences are
then resampled over episodes with 10,000 deterministic bootstrap replicates.
