\begin{abstract}
Long-term agent memory is usually evaluated as a semantic-ranking problem.  Yet a
memory can answer a query while belonging to the wrong principal, violating policy,
or representing an incompatible state.  We formulate \emph{retrieval admissibility}
as a query-conditioned, three-valued verification target and trace each record from
storage through retrieval, prompt exposure, and answer disclosure.  Our matched-recall
protocol separates historical non-usability from admissibility-only risk and reports
partial-identification bounds when labels are unresolved.  On frozen rankings over
\NaturalQueryCount{} public-source queries, trusted namespace support improves
top-20 recall from \TopTwentyGlobalRecall{} to \TopTwentyNamespaceRecall{} and
reduces penalized admissibility upper risk from \TopTwentyGlobalAdmRisk{} to
\TopTwentyNamespaceAdmRisk{}.  The effect persists at every tested budget, but is
metadata-dependent: released policy filtering helps, whereas the evaluated coarse
lifecycle-only rule hurts; false-deny and namespace-swap errors erase joint
utility--risk dominance earlier than fail-open errors.  Released metadata exposes
risk headroom (\ReleasedOracleAdmRiskDelta{}, 95\% CI
\ReleasedOracleAdmRiskDeltaCI{}), but text-only verification does not recover it:
GPT-5.6 reduces recall and increases risk, while controlled verifiers overflip
unchanged candidates at rates \GPTControlledOverflip{}--\GeminiControlledOverflip{}.
Finally, assigned exposure has different disclosure effects under constructed
admissible and inadmissible query conditions, yet one reader retains a positive
relevant-inadmissible effect.  These results identify governance-metadata reliability
and selective verification---not ranking alone or reader restraint---as the central
bottleneck.  We contribute an auditable evaluation protocol and empirical diagnosis,
not a new memory index or a production-safety claim.
\end{abstract}

\section{Introduction}

Persistent memory lets an agent accumulate user facts, task experience, and
environment state beyond one context window.  Existing evaluations therefore ask
whether the system can recover evidence from long histories
\citep{wu2025longmemeval,wu2026longmemevalv2,zhang2026rhelm}.  That question misses a
deployment-critical distinction.  Figure~\ref{fig:pipeline} shows four cases from
our audited public-source packets.  A market query retrieves a topically similar
market memory from another principal.  A current Lisbon-departure query encounters
an invalidated March 7 record after March 14 has been confirmed.  A phone-memory
request must retain model and carrier details while withholding a battery habit the
user explicitly asked the system to forget.  Conversely, superseded dose schedules
remain necessary when a query asks how metformin timing changed over time.  The same
stored record can therefore be usable, inadmissible, or unresolved depending on the
query, principal, policy, and time.  Recent benchmarks expose individual parts of
this problem through
shared-memory governance \citep{ren2026gatemem,mireshghallah2026cimemories}, explicit
lifecycle operations \citep{hao2026memops}, and stale-state reasoning
\citep{chao2026stale}.  What is still missing is a compact verification object that
can be measured at retrieval time and traced to downstream use.

We study this gap as an evaluation problem rather than proposing another memory
architecture.  Our central object is \emph{query-conditioned admissibility}: whether
a memory is within scope, policy-allowed, and lifecycle-compatible for a particular
query and time.  The verification layer checks each ranked candidate, emits an
explicit use/drop reason, and preserves its identity through four observable stages:
stored, retrieved, exposed, and disclosed.  This makes failures localizable.  A
store can contain inadmissible material without retrieving it; a router can retrieve
a candidate without exposing it; and a reader can be exposed to a target without
disclosing it in the answer.

This framing yields a layered empirical question.  Removing impossible evidence
from candidate support should help semantic ranking when governance metadata is
trustworthy.  That benefit should depend on the \emph{direction} of metadata error:
false denial deletes required evidence, whereas false allowance expands the attack
and contamination surface.  If released fields expose useful headroom, a deployable
text-only verifier must recover it without rejecting stable evidence.  Finally, if an
inadmissible record reaches the prompt, reader compliance must not be assumed to be
an enforcement boundary.  Our experiments test these links separately rather than
collapsing them into one end-to-end score.

Our contributions are:
\begin{itemize}
  \item a three-valued distinction between relevance, admissibility, and usability,
  together with a stored--retrieved--exposed--disclosed observation model;
  \item matched-recall non-usable and admissibility risk families with explicit label
  coverage, sharp bounds, and an infeasibility decomposition;
  \item a hash-bound natural audit showing fixed-budget support gains, policy-versus-
  lifecycle attribution, and asymmetric failure under metadata corruption; and
  \item two complementary tests of the enforcement boundary: natural and controlled
  text-only verification diagnostics, followed by a paired prompt-exposure
  intervention across three separately reported readers.
\end{itemize}

\section{Related Work}

\paragraph{Long-term memory evaluation.}
LongMemEval decomposes memory systems into indexing, retrieval, and reading and
tests extraction, multi-session reasoning, temporal reasoning, updates, and
abstention \citep{wu2025longmemeval}.  LongMemEval-V2 extends evaluation to
environment experience and explicitly measures context gathering and latency
\citep{wu2026longmemevalv2}.  RHELM introduces heterogeneous, temporally evolving
sources \citep{zhang2026rhelm}, while MemOps evaluates explicit remember, forget,
update, and reflection operations \citep{hao2026memops}.  These resources motivate
our focus on evidence state and provenance rather than treating memory as a static
bag of facts.

\paragraph{Governance and contextual validity.}
GateMem evaluates utility, access control, and active forgetting in multi-principal
memory \citep{ren2026gatemem}; CIMemories studies context-dependent information-flow
violations \citep{mireshghallah2026cimemories}; and STALE tests whether models reject
invalidated premises \citep{chao2026stale}.  RaMem is the closest retrieval-method
comparison: it addresses context collapse by anchoring episodic conditions, inducing
query recall conditions, retrieving context-compatible memories, and preserving
their context for synthesis \citep{yang2026ramem}.  Our object is different.  We
evaluate heterogeneous governance eligibility across scope, policy, and lifecycle,
retain unresolved labels, perturb metadata reliability, and trace pre-prompt
enforcement through disclosure.  The released populations and system interfaces do
not support a faithful direct RaMem baseline, so we cite and contrast it rather than
retrofit an incomparable implementation.  More broadly, we do not replace the above
benchmarks; we define a common retrieval-time verification layer without collapsing
scope, lifecycle, exposure, and answer disclosure.

\paragraph{Analytical agent evaluation.}
AgentBench and AgentBoard broaden agent evaluation beyond static language tasks
\citep{liu2024agentbench,ma2024agentboard}; HELM emphasizes multi-metric transparent
evaluation \citep{liang2023helm}.  Our protocol follows this analytical stance:
final-answer accuracy alone cannot tell whether an answer was supported by
admissible evidence.  Because model-based evaluation can introduce systematic
biases \citep{liu2023geval}, we report reader identities separately and do not pool
their estimates.

\section{Retrieval Admissibility Methodology}

Our contribution is an evaluation methodology rather than a latent-state classifier
or a new memory index.  It combines (i) query-conditioned, three-valued evidence
assessment, (ii) an observable retrieval-to-answer trace, and (iii) matched-recall
risk estimates that remain valid when some candidate labels are unresolved.

\subsection{Query-conditioned, three-valued evidence}

Let $z=(q,p,\rho,t)$ denote an evaluation context containing the query, authenticated
principal, governing policy, and time.  For memory $m$, the verifier records
relevance $r_z(m)$, namespace or scope membership $n_z(m)$, policy permission
$g_z(m)$, and lifecycle compatibility $\ell_z(m)$.  Every axis takes a value in
$\mathcal{T}=\{1,0,?\}$: established positive, established negative, or unresolved.
We use the conservative three-valued conjunction
\begin{equation}
\bigwedge\nolimits_{3}(x_1,\ldots,x_d)=
\begin{cases}
0, & \exists j:x_j=0,\\
1, & \forall j:x_j=1,\\
?, & \text{otherwise}.
\end{cases}
\label{eq:three-valued}
\end{equation}
Admissibility and usability are therefore statuses of a memory--context pair:
\begin{align}
a_z(m)&=\bigwedge\nolimits_{3}\!\left(n_z(m),g_z(m),\ell_z(m)\right),
\label{eq:admissible}\\
u_z(m)&=\bigwedge\nolimits_{3}\!\left(r_z(m),a_z(m)\right).
\label{eq:usable}
\end{align}
The positive admissible and usable sets are
$\mathcal{A}_z=\{m:a_z(m)=1\}$ and
$\mathcal{U}_z=\{m:u_z(m)=1\}$; corresponding negative and unresolved sets use
status 0 and $?$.  Equation~\ref{eq:three-valued} makes the decision rule explicit:
one known violation is sufficient to reject a candidate, positive usability requires
all four positive labels, and missing information never becomes an implicit pass.
With complete binary labels, Equations~\ref{eq:admissible}--\ref{eq:usable} reduce
to the familiar set intersections
$\mathcal{A}_z=\mathcal{N}_z\cap\mathcal{P}_z\cap\mathcal{L}_z$ and
$\mathcal{U}_z=\mathcal{R}_z\cap\mathcal{A}_z$.

Lifecycle compatibility is relational rather than an intrinsic record property.  In
our released-field mapping, current records are compatible with both intents; stale
or superseded records are compatible with history but not current-state queries; an
unknown state or intent remains unresolved (Appendix~\ref{app:metric-details}).
Thus a superseded value can be prohibited for ``what is current?'' yet required for
``how did it change?''  This is an evaluation rule, not a claim that intent or state
can be inferred from raw text.

\subsection{Verification operator and observable trace}

For each returned ID, the verifier emits $u_z(m)$, every known axis-level exclusion
reason, and unresolved status.  Authenticated namespace metadata, when trusted and
complete, can additionally restrict ranking support to
$\mathcal{C}^{N}_z=\{m\in\mathcal{M}:n_z(m)=1\}$ instead of the global store
$\mathcal{M}$.  The exact operators are in Appendix~\ref{app:metric-details}.  The
protocol does not infer or silently complete missing provenance.

For route $a$, we preserve memory identity through three record-level indicators:
$S_m$ for stored, $R_{qma}$ for returned, and $E_{qma}$ for included in the assembled
prompt.  The system construction gives $E_{qma}\leq R_{qma}\leq S_m$.  We separately
record $Y_{qa}$, whether the protected target is detected in the answer.  There is no
deterministic implication from $E$ to $Y$: a reader may ignore exposed content or
produce the target without that record.  The trace localizes failure without claiming
access to the reader's internal reasoning.

\subsection{Matched-recall risk under incomplete labels}
\label{sec:matched-risk}

Let $\mathcal{G}_q\subseteq\mathcal{U}_z$ be the known usable evidence anchors for
query $q$, and let route $a$ return
$\pi_{qa}=(m_1,\ldots,m_n)$.  Prefix recall and feasibility at target $\tau$ are
\begin{align}
\operatorname{Rec}_{qa}(k)
&=\frac{|\{m_1,\ldots,m_k\}\cap\mathcal{G}_q|}{|\mathcal{G}_q|},\\
F_{qa}(\tau)
&=\mathbf{1}\!\left\{\operatorname{Rec}_{qa}(n)\geq\tau\right\}.
\end{align}
For a feasible route, the matched prefix is
\begin{equation}
k^*_{qa}(\tau)=\min\{k:\operatorname{Rec}_{qa}(k)\geq\tau\},\qquad
P_{qa}(\tau)=\{m_1,\ldots,m_{k^*_{qa}(\tau)}\}.
\label{eq:matched-prefix}
\end{equation}
Using the smallest qualifying prefix charges a method for every item ranked before
the target is reached and compares contamination after every feasible method reaches
the same anchor-recall target.

We score two status families on the same prefix.  Let
$s_z^{U}(m)=u_z(m)$ denote usability and $s_z^{A}(m)=a_z(m)$ denote
admissibility.  For $B\in\{U,A\}$, let $c^B$, $v^B$, and $h^B$ count items with
$s_z^B(m)=0,1,?$ in a nonempty matched prefix, so
$N=c^B+v^B+h^B$.  The resolved-only estimate, label coverage, and
assumption-free bounds are
\begin{align}
C^{K,B}_{qa}&=\frac{c^B}{c^B+v^B}, &
\gamma^B_{qa}&=\frac{c^B+v^B}{N},\label{eq:known-coverage}\\
C^{L,B}_{qa}&=\frac{c^B}{N}=\gamma^B_{qa}C^{K,B}_{qa}, &
C^{U,B}_{qa}&=\frac{c^B+h^B}{N}
=\gamma^B_{qa}C^{K,B}_{qa}+(1-\gamma^B_{qa}).
\label{eq:partial-id}
\end{align}
These identities show exactly what incomplete labels cost:
$C^{U,B}_{qa}-C^{L,B}_{qa}=1-\gamma^B_{qa}$.  The interval is the sharp
partial-identification region obtained by assigning every unresolved item first to
the positive and then to the negative class.  If all items are unresolved,
$C^{K,B}$ is undefined but $[C^{L,B},C^{U,B}]=[0,1]$ remains defined.  The two
families answer different questions: $B=U$ counts irrelevant-but-admissible evidence
as non-usable, whereas $B=A$ counts only scope, policy, or lifecycle violations.

Recall failure must not appear perfectly safe.  On the recall-evaluable population
$\mathcal{Q}^{+}=\{q:|\mathcal{G}_q|>0\}$, define
\begin{align}
\widetilde C^{U,B}_{qa}(\tau)
&=\begin{cases}
C^{U,B}_{qa}, & F_{qa}(\tau)=1,\\
1, & F_{qa}(\tau)=0,
\end{cases}\label{eq:penalized-query-risk}\\
\operatorname{PCR}^{B}_{a}(\tau)
&=\frac{1}{|\mathcal{Q}^{+}|}
  \sum_{q\in\mathcal{Q}^{+}}\widetilde C^{U,B}_{qa}(\tau).
\label{eq:penalized-risk}
\end{align}
Equation~\ref{eq:penalized-risk} is always qualified by its status family.  The
historical frozen experiment selected settings with
$\operatorname{PCR}^{U}$, the \emph{penalized non-usable upper risk}; it cannot be
renamed as pure inadmissibility.  The post-hoc v2 decomposition re-scores the frozen
rankings with $\operatorname{PCR}^{A}$, the \emph{penalized admissibility upper
risk}.  Neither is a conditional contamination estimate.  The aggregate separates
exactly as
\begin{equation}
\operatorname{PCR}^{B}_{a}
=\underbrace{\frac{1}{|\mathcal{Q}^{+}|}\sum_{q\in\mathcal{Q}^{+}}(1-F_{qa})}_{\text{infeasibility}}
+\underbrace{\frac{1}{|\mathcal{Q}^{+}|}\sum_{q\in\mathcal{Q}^{+}}
F_{qa}C^{U,B}_{qa}}_{\text{feasible-prefix contribution}}.
\label{eq:risk-decomposition}
\end{equation}
We therefore report both components, feasible rate, and the conditional
$C^{K,B}$, $\gamma^B$, $C^{L,B}$, and $C^{U,B}$.  Queries without known anchors
are recall-unevaluable, not assigned zero.  Axis-specific matched-prefix violations
localize scope, policy, and lifecycle errors; their formula is in
Appendix~\ref{app:metric-details}.  Prompt exposure is measured separately.

\subsection{Exposure--disclosure and safety--utility estimands}

Let $X_{qa}$ indicate that a protected target is exposed in route $a$'s assembled
prompt and let $Y_{qa}$ indicate disclosure in its answer.  For checkpoint $q$, form
the ordered discordant pairs
$D_q=\{(a,b):X_{qa}=1,\ X_{qb}=0\}$.  To avoid overweighting checkpoints with more
route pairs, we first average within checkpoint and then across checkpoints:
\begin{equation}
d_q=\frac{1}{|D_q|}\sum_{(a,b)\in D_q}(Y_{qa}-Y_{qb}),\qquad
\widehat{\mathrm{RD}}=\frac{1}{|\mathcal{Q}_D|}
\sum_{q\in\mathcal{Q}_D}d_q.
\label{eq:discordant-rd}
\end{equation}
We also test whether exposure adds out-of-episode predictive information beyond
route identity, domain, query type, non-emptiness, and route width.  Neither analysis
is causal because exposure is not randomized.

The controlled intervention instead fixes the query and background candidates and
changes only whether one manipulated candidate is included.  For paired unit $i$ in
relevance--admissibility cell $c$, let $D_i(1)$ and $D_i(0)$ indicate literal target
disclosure with that candidate exposed and withheld.  We estimate
\begin{equation}
\hat{\Delta}_c=\frac{1}{n_c}\sum_{i\in c}\bigl[D_i(1)-D_i(0)\bigr],\qquad
\hat{S}=\hat{\Delta}_{\mathrm{rel,adm}}-
\hat{\Delta}_{\mathrm{rel,inadm}}.
\label{eq:paired-exposure}
\end{equation}
Here $\hat{S}$ is the \emph{selectivity gap}: exposure should enable relevant
admissible evidence without similarly increasing disclosure of relevant inadmissible
evidence.  This identifies a prompt-level effect in the constructed population, not
internal model use or natural-history prevalence.

A stricter route is not summarized by leakage alone: we report leakage, utility, and
refusal deltas on their respective eligible populations, never pooling the three
(Appendix~\ref{app:metric-details}).  The resulting contract gives every verdict an
axis-level reason, every retrieval comparison a recall constraint and uncertainty
interval, and every downstream claim an explicit observable stage.

\paragraph{Natural retrieval and robustness.}
The main audit combines public RHELM and MemOps sources
\citep{zhang2026rhelm,hao2026memops}.  Development contains 23 disjoint groups,
45,978 memories, and 1,104 queries; evaluation contains \NaturalGroupCount{} groups,
\NaturalMemoryCount{} memories, and \NaturalQueryCount{} queries.  Released evidence
IDs, provenance, and deterministic operation replay provide anchors and states; there
is no candidate subsampling, positive injection, or human-overlap label.  Nine frozen
arms share a pinned Qwen3-Embedding-8B revision and exact inner-product ranking.  A
165-setting grid is selected on development with the historical v1 non-usable risk;
the \NaturalRouteRows{} evaluation routes receive no retuning or repair
(Appendix~\ref{app:arms}).  We post-hoc re-score frozen global/namespace prefixes at
$k\in\{10,20,50,100\}$ with v2 admissibility risk and separately evaluate corrected
\texttt{released\_governance\_oracle\_v2} semantics without tuning.

Corruption changes only method-visible metadata; labels, embeddings, dense scores,
and settings stay fixed.  False allow, false deny, missingness, and namespace swap are
nested over ten seeds at rates $\{0,.02,.05,.10,.20,.30,.40,.50\}$.  Support-expanding
false allow and source swap trigger full-corpus reranking.  Dominance requires no lower
feasibility and no higher v2 risk; reported break-even values are adjacent observed
grid points, not interpolated thresholds.

\paragraph{Inference and exposure.}
The natural diagnostic fixes top-20 pools for 96 public-development cases, selecting
thresholds on 24 and applying them once to 72.  Released fields define an oracle;
\texttt{gpt-5.6-sol} and \texttt{gemini-3.6-flash} infer from text and are reported
separately.  A separate 16-scenario diagnostic varies principal, policy purpose,
lifecycle intent, or as-of time, with 32 focal and 64 stable pairs; support requires
focal consistency $\geq.80$ and stable overflip $\leq.05$.

The paired exposure experiment uses the same four axes in \ExposureScenarioCount{}
constructed scenarios.  With query and background fixed, one candidate is withheld
or exposed, yielding \ExposurePairsPerReader{} paired units and 384 requests for each
of GPT-5.6, Gemini 3.6, and DeepSeek V4 Pro.  A literal scorer, one attempt, and no
judge, repair, selective rerun, or pooling are used (Appendix~\ref{app:paired-construction}).
Appendices~\ref{app:gatemem} and \ref{app:smoke} report the observational GateMem audit
\citep{ren2026gatemem} and the candidate-pool implementation smoke.

\paragraph{Outcomes and boundaries.}
Historical v1 and post-hoc v2 risks retain distinct names.  We report recall,
feasibility at $\tau=.8$, v2 risk and its two components, typed violations, and work.
Fixed-budget, controlled-verification, and paired-exposure intervals use 10,000
source- or scenario-clustered replicates; corruption means are descriptive.  The
natural run has no downstream reader and is not an official benchmark score; candidate
counts are not production cost.  All values are hash-bound normalized evidence.

\subsection{Trusted support helps at practical retrieval budgets}

The namespace advantage is already visible at top-20, not only top-100
(Figure~\ref{fig:constraint-reliability}a).  Recall rises from
\TopTwentyGlobalRecall{} to \TopTwentyNamespaceRecall{} (difference
\TopTwentyRecallDelta{}, 95\% CI \TopTwentyRecallDeltaCI{}), feasible rate from
\TopTwentyGlobalFeasible{} to \TopTwentyNamespaceFeasible{}
(\TopTwentyFeasibleDelta{}, \TopTwentyFeasibleDeltaCI{}), and penalized
admissibility upper risk falls from \TopTwentyGlobalAdmRisk{} to
\TopTwentyNamespaceAdmRisk{} (difference \TopTwentyAdmRiskDelta{},
\TopTwentyAdmRiskDeltaCI{}).  At top-100 the respective deltas are
\TopHundredRecallDelta{}, \TopHundredFeasibleDelta{}, and
\TopHundredAdmRiskDelta{}.  Every interval at all four tested budgets excludes zero.

The risk decomposition prevents a feasibility gain from masquerading as cleaner
feasible prefixes.  At top-100, the total \TopHundredAdmRiskDelta{} difference is the
sum of an infeasibility component \TopHundredInfeasibilityDelta{} and a
feasible-prefix admissibility component \TopHundredConditionalAdmDelta{}; both
intervals exclude zero.  These are post-hoc v2 scores on frozen rankings.  The
historical preregistered v1 result remains the penalized \emph{non-usable} upper risk
and is reported separately in Appendix~\ref{app:arms}.

\subsection{Metadata errors are directionally asymmetric}

Corrected attribution changes the earlier lifecycle interpretation
(Figure~\ref{fig:constraint-reliability}b).  Policy-only filtering changes recall by
\PolicyOnlyRecallDelta{} (\PolicyOnlyRecallDeltaCI{}), feasible rate by
\PolicyOnlyFeasibleDelta{} (\PolicyOnlyFeasibleDeltaCI{}), and admissibility risk by
\PolicyOnlyAdmRiskDelta{} (\PolicyOnlyAdmRiskDeltaCI{}).  Lifecycle-only filtering
instead changes recall by \LifecycleOnlyRecallDelta{} and risk by
\LifecycleOnlyAdmRiskDelta{}: the evaluated two-intent rule removes useful evidence.
The corrected combined v2 arm remains beneficial, but less so than policy alone.
Thus the incremental gain is policy-driven, not lifecycle-only headroom.

Corruption confirms that error direction matters.  Policy false denial and
lifecycle false-stale lose joint dominance at the first nonzero .02 grid point.
Namespace false deny, missing labels, and source-level swaps dominate through .10 and
first fail at .20.  Policy false allow and fail-open missing dominate through .30 and
first fail at .40.  Query-memory namespace false allow remains jointly dominant
through the tested .50 point, but that aggregate verdict is not safety: at .50 its
matched-prefix wrong-scope exposure is \FalseAllowHalfWrongScope{} and it scores
\FalseAllowHalfCandidates{} candidates per query, versus roughly 1,551 when clean.
Source-level label swap first fails at .20, where recall is
\NamespaceSwapTwentyRecall{} and feasible rate \NamespaceSwapTwentyFeasible{}.
These are observed grid brackets under specific corruption mechanisms, not universal
accuracy thresholds.

\subsection{Text-only verification does not recover released governance state}

The released oracle preserves recall and feasibility while reducing admissibility
risk by \ReleasedOracleAdmRiskDelta{} (\ReleasedOracleAdmRiskDeltaCI{};
Figure~\ref{fig:inference-gap}a).  GPT-5.6 text filtering instead changes recall by
\OpenAIInferredRecallDelta{} (\OpenAIInferredRecallDeltaCI{}), feasible rate by
\OpenAIInferredFeasibleDelta{} (\OpenAIInferredFeasibleDeltaCI{}), and risk by
\OpenAIInferredAdmRiskDelta{} (\OpenAIInferredAdmRiskDeltaCI{}).  Gemini does not
realize the oracle benefit either.  Its admissibility ROC-AUC is
\GeminiInferredRocAuc{}, versus \OpenAIInferredRocAuc{} for GPT-5.6; their violation
recalls are only \GeminiInferredViolationRecall{} and
\OpenAIInferredViolationRecall{}.  The models occupy different precision--recall
points, but neither converts released-field headroom into a utility-preserving route.

Controlled pairs expose the mechanism (Figure~\ref{fig:inference-gap}c).  GPT-5.6
and Gemini classify all focal flips correctly, while DeepSeek reaches
\DeepSeekControlledFocalConsistency{}.  Yet stable-control overflip is
\GPTControlledOverflip{}, \GeminiControlledOverflip{}, and
\DeepSeekControlledOverflip{}, all above the frozen .05 ceiling.  Post-hoc errors are
dominated by false denial of stable-admissible memories
(\GPTControlledStableFalseDeny{}, \GeminiControlledStableFalseDeny{}, and
\DeepSeekControlledStableFalseDeny{}) rather than false admission of stable-
inadmissible controls.  Strong focal rule-following therefore does not establish
selective verification.

\subsection{Reader restraint is not an enforcement boundary}

Relevant-admissible exposure effects are \OpenAIExposureAdmissible{},
\GeminiExposureAdmissible{}, and \DeepSeekExposureAdmissible{} for GPT-5.6, Gemini,
and DeepSeek (Figure~\ref{fig:paired-exposure}).  Their selectivity gaps are
\OpenAIExposureGap{}, \GeminiExposureGap{}, and \DeepSeekExposureGap{}; every
interval excludes zero.  DeepSeek nevertheless retains a relevant-inadmissible effect
of \DeepSeekExposureInadmissible{} (\DeepSeekExposureInadmissibleCI{}).  Thus assigned
exposure has different effects under the constructed query conditions, but neither
admissibility as an isolated moderator nor internal model use is identified.

\paragraph{Secondary diagnostics.}
The frozen threshold arm loses recall and the cluster arm is practically
indistinguishable from namespace dense (Appendix Figure~\ref{fig:retrieval}).
Observational GateMem traces associate exposure with disclosure and expose a
leakage--utility--over-refusal trade-off (Appendix Figure~\ref{fig:gatemem-observational});
they are not pooled with the natural or controlled experiments.

\section{Discussion}

\paragraph{Metadata reliability, not one accuracy number.}
Semantic ranking improves after impossible evidence leaves its support, but false
denial removes required evidence while false allowance expands scope, exposure, and
work.  The released oracle has headroom, yet text-only filters fail to realize it and
reject stable candidates.  Governance state is therefore not interchangeable with a
semantic feature; systems should preserve authenticated provenance and abstain when
state is unresolved.

\paragraph{Verification before reading.}
Reader selectivity cannot substitute for enforcement.  Eligibility should be checked
before prompt assembly, with exclusions and unresolved cases logged.  The four-stage
trace then separates retrieval, exposure, and disclosure, while matched-recall bounds
prevent apparent safety through recall failure or silent label imputation.

\paragraph{A diagnostic contribution.}
The evaluated router refinements add no utility beyond namespace dense.  The evidence
instead supports a staged pattern: trusted metadata constrains support, a pre-prompt
verifier records decisions, semantic ranking operates within feasible support, and
the reader remains auditable but is not the enforcement boundary.

\section{Limitations and Broader Impact}

The natural audit covers two public-source families, uses released metadata, and has
no downstream reader.  Corruptions are controlled mechanisms; their grid brackets
are not population thresholds.  V2 scoring is post-hoc on frozen rankings, whereas
selection used v1 non-usable risk.  Policy is a released approximation, lifecycle has
two intents, candidate counts are not production cost, and the natural and controlled
inference populations contain only 72 cases and 16 scenarios, respectively.

GateMem is observational, same-provider, and uses distinct utility and leakage
populations.  Paired exposure uses constructed queries, literal markers, and a
rule-based scorer; it does not isolate admissibility from all query changes or measure
internal use or natural prevalence.  Filters can suppress legitimate evidence, so
deployments should log exclusions and evaluate matched-recall utility.  We release
only content-free aggregates and hashes, not conversations, responses, or private data.

\section{Conclusion}

Long-term memory verification should ask whether evidence is admissible, not merely
relevant.  Trusted support improves frozen rankings, but its value depends on error
direction; text-only inference and reader restraint do not replace authenticated
metadata and pre-prompt enforcement.  Memory safety is therefore an evidence-
eligibility and metadata-reliability problem, not ranking alone.

\section{Metric Details}
\label{app:metric-details}

For completeness, the released-field lifecycle rule used in Section~3.1 is
\begin{equation}
\ell_z(m)=
\begin{cases}
1, & s_m=\text{current},\\
1, & s_m\in\{\text{stale},\text{superseded}\},\ i_q=\text{history},\\
0, & s_m\in\{\text{stale},\text{superseded}\},\ i_q=\text{current},\\
?, & s_m=\text{unknown}\ \text{or}\ i_q=\text{unknown}.
\end{cases}
\label{eq:lifecycle}
\end{equation}
Writing $x_{zj}(m)$ for the recorded label on admissibility axis $j$, the verifier's
known exclusion reasons and trusted-namespace support are
\begin{align}
\operatorname{reason}_z(m)
&=\{j\in\{\mathrm{scope},\mathrm{policy},\mathrm{lifecycle}\}:x_{zj}(m)=0\},
\label{eq:reasons}\\
\mathcal{C}^{N}_z&=\{m\in\mathcal{M}:n_z(m)=1\},\qquad
\pi^{N}_z=\operatorname{Rank}(q;\mathcal{C}^{N}_z).
\label{eq:namespace-support}
\end{align}
For a feasible matched prefix of size $N$, the typed violation rate is
\begin{equation}
V^{(j)}_{qa}=\frac{1}{N}\sum_{m\in P_{qa}(\tau)}
\mathbf{1}\{x_{zj}(m)=0\},
\quad j\in\{\mathrm{scope},\mathrm{policy},\mathrm{lifecycle}\}.
\label{eq:typed-violation}
\end{equation}
Finally, for leakage, utility, or refusal outcome $j$ and its own eligible population
$\mathcal{Q}_j$, the strict-minus-base contrast is
\begin{equation}
\Delta_j=\frac{1}{|\mathcal{Q}_j|}\sum_{q\in\mathcal{Q}_j}
\left(Y^{(j)}_{q,\mathrm{strict}}-Y^{(j)}_{q,\mathrm{base}}\right).
\label{eq:safety-utility}
\end{equation}

For a matched prefix, a known-rate estimate is undefined when every status in its
chosen family is unresolved; the lower and upper bounds remain defined.  Queries with no known usable anchors are
excluded from recall averages, and the evaluable rate is reported separately.  Macro
averages never impute missing query metrics.  Duplicate ranked memory identifiers,
missing assessments, negative runtime measurements, and non-finite values are
rejected by the reference implementation.

\section{Natural-Corpus Construction and Arms}
\label{app:arms}

RHELM development uses the first three persona-hash groups; evaluation uses the
remaining seven.  For each query, only conversation turns strictly earlier than its
date are candidates.  MemOps development uses the first 20\% of profile-hash groups;
evaluation uses the remaining 80 profiles.  Every method-visible dialogue memory in
the split is a global candidate.  MemOps has no cross-case wall clock, so its recency
arm uses released source order and is not a temporal-freshness claim.

All dense arms use \texttt{Qwen/Qwen3-Embedding-8B} at revision
\nolinkurl{1d8ad4ca9b3dd8059ad90a75d4983776a23d44af}, maximum length 512,
unit-normalized last-token pooling, float32 vectors, exact inner product, and stable
memory-ID tie breaking.  For unit vectors,
\[
s_{\mathrm{dense}}(m,q)=e_m^\top e_q.
\]
The hybrid arm uses reciprocal-rank fusion
\[
s_{\mathrm{RRF}}(m,q)=
\frac{1}{60+\operatorname{rank}_{\mathrm{BM25}}(m)}
+
\frac{1}{60+\operatorname{rank}_{\mathrm{dense}}(m)},
\]
and the recency control uses
$s_{\mathrm{rec}}(m,q)=s_{\mathrm{dense}}(m,q)+\gamma\rho(m)$, where
$\rho(m)\in[0,1]$ is normalized released order.

The threshold router incrementally assigns a memory to its most similar namespace
centroid when $\max_k\cos(e_m,c_k)\geq\theta$ and otherwise creates a cluster.  At
query time it selects at most $L$ centroids above $\theta$.  The cluster router uses
\[
\ell_k(x)=\gamma\log(n_k+\beta)+\frac{\cos(x,c_k)}{\tau},
\qquad
\ell_{\mathrm{new}}(x)=\log\alpha+
\frac{1-\max_j\cos(x,c_j)}{\tau_{\mathrm{new}}},
\]
assigns by the largest existing-or-new score, and routes over existing clusters.
An empty route in either router falls back to namespace-local dense retrieval.

\section{GateMem Routing, Scoring, and Prediction}
\label{app:gatemem}

G0 is the exact upstream \texttt{rag\_naive} global TF--IDF route and G1 is the
upstream \texttt{rag\_policy} route with released policy logic.  G2 starts at the
authenticated asker, forms a connected component from explicit relationship IDs,
and admits chunks spoken by principals in that component; it reads neither query or
memory text nor leak targets when deciding support.  G3 adds only explicit pre-query
delete or supersede operations.  Because the release contains none, G3 is
trace-identical to G2.  G0 and G1 are upstream methods; G2 and G3 are diagnostics.

Each reader prompt contains the question and ordered retrieved record IDs and texts,
but not the arm name, scores, target strings, expected action, or gold answer.  Both
readers use temperature zero, JSON mode, and at most 384 output tokens.  The runs are
fresh, with no judge or output repair.  A strict parser accepts one object containing
action, answer, structured answer, and a string-list audit field; the audit field is
not scored, and parse failures receive conservative outcomes.

  disclosure over \ReaderDiscordantCount{} discordant checkpoints.  (b) Predictive

Privacy checkpoints use the released privacy context-leak and answer-leak rules;
safety checkpoints use the corresponding deletion rules.  The disclosure outcome
is the released rule-based end-to-end target indicator.  Utility correctness and
over-refusal are bounded rule-based auxiliary outcomes rather than LLM-judge scores.
Parse failures are handled conservatively as leakage for privacy or safety and as
incorrect plus over-refusal for utility.

The incremental predictor is logistic regression with $C=1$, the \texttt{lbfgs}
solver, and at most 2,000 iterations.  Categorical features are arm, domain, and
query type; additional baseline features are route non-emptiness and standardized
route width.  The augmented model adds only target exposure.  Each held-out episode
is scored by a model fit on all other episodes.  Brier and log-loss differences are
then resampled over episodes with 10,000 deterministic bootstrap replicates.

\section{Controlled Exposure Construction}
\label{app:paired-construction}

Each of the 16 scenarios has two paraphrased query pairs, allow and block conditions,
and three manipulated roles: a relevant focal candidate, an irrelevant-admissible
candidate, and an irrelevant-inadmissible candidate.  The focal candidate is
admissible under allow and inadmissible under block.  For every
query--condition--candidate unit, two requests differ only in whether that candidate
is exposed.  This yields 192 paired units and 384 requests for each reader.

Every candidate carries a unique literal marker absent from the query and all other
candidates.  The normalized-substring scorer counts the marker even inside a refusal;
appearance after withholding is hallucinated disclosure.  Requests are stateless,
temperature-zero, and deterministically interleaved.  All three readers complete the
panel with one attempt per request.  There is no transport retry, judge, output
repair, selective rerun, or model pooling.  The released result package contains only
content-free pair scores, aggregates, hashes, costs, and bootstrap intervals.
